# Changelog

## 1.0.0

Released 2026-10-18. First version.

- `hsb-init` sets a project up: `HYPER-SECOND-BRAIN.md` (the package's general rules for the vault, including how notes and documents are treated), `project.md` with the PARA folder map and a place for the user's lasting choices, the pointer line in the agent's instruction file, and the vault with its missing PARA folders.
- `hsb-doctor` checks the setup and the vault's state, and repairs the package's own files; it tells when `HYPER-SECOND-BRAIN.md` names a skill that is not installed or differs from the template of the installed version, and refreshes it on the user's yes, keeping the user's own lines (the manifest records the template the file came from).
- `hsb-update` brings an installed setup to a newer version and ends with a full `hsb-doctor`.
- `hsb-place-an-item` decides where a note or a file goes in the vault and puts it there, by the general rules in `HYPER-SECOND-BRAIN.md` (the categories, folder names, what the agent may do and must ask first, links, language, data and secrets, the Project List) and the rules of placing in its own reference.
- `hsb-projects` keeps the Project List and runs a project's start, changes, and finish; the questions it leaves open wait in `hyper-second-brain/state.json`, and `hsb-doctor` checks that the list and the project folders agree.
- `hsb-review` runs the weekly and monthly reviews, archives a piled-up Inbox whole, and moves material when the user's roles or interests change; the review dates wait in `hyper-second-brain/state.json`, the agent offers a review that is due, and `hsb-doctor` reports it.
- `hsb-find` finds what the vault holds and says where (its search ignores letter case and the form of the apostrophe), gathers past work and evidence, states where a project stands, prepares meetings, and lists the material toward stuck work; the agent looks in the vault before it researches, drafts, or proposes.
- `hsb-capture` decides what is worth keeping, keeps the key points of a source as a short note with its source line, keeps the user's favorite problems (the weekly review tests new items against them), and brings findings from other apps into the Inbox.
- `hsb-distill` marks the main points of notes in layers without changing their text, marks meeting decisions and action items, and summarizes a note; every note the agent writes answers five questions of the rules file, and the agent shows a note's most condensed part first.
- `hsb-create` prepares focused work, helps in the exploring or the finishing mode, keeps a "Where I left off" note per project, assembles a deliverable from saved notes, outlines a piece of writing, and keeps reusable pieces and feedback; `hsb-projects` offers its outline at a project's start and its final entry when a project stops, `hsb-find` reads that note for a project's state, and the weekly review suggests a first output for a top project.
- `hsb-share` prepares a note for other readers without personal details, gives feedback on a draft for others, and says what goes to a shared platform when work becomes shared; it sends nothing.
- `hsb-restart` archives the whole vault into one dated folder after the user's yes, with a way back, and rebuilds the Project List and the project folders from the current projects; it walks a new user through getting started in stages; the reorganize script has a `restart` command.
- `hsb-connect` gives notes tags, typed links (`up`, `related`, `source`, and others the vault needs) and maps of content in their properties without changing their text, by a standard agreed with the user in `hyper-second-brain/tags.md`; its script measures the vault, writes the properties, makes and extends the maps, checks the result and takes a batch back; the rules file asks every skill that creates or places a note to follow the standard.
- `hsb-re-organize` repairs links written as a full path from an Obsidian vault one folder above the vault, matches names in composed and decomposed Unicode, rewrites links that spell the old letter case of a renamed folder, gives the git commands that record a rename of letter case only when git ignores letter case, keeps its way back in a vault with names in other scripts, names the settings, templates and instruction files that write a folder's old path, leaves out the signs that repeat by design (a year in a title, empty notes, copies of a template, names in many folders, and the user's `Ignore names` and `Not projects` lines), reads compact cards first, and describes folders without moving anything when the user asks; an `_about.md` is written in the vault's main language.
- The CLI installs, updates, removes and reports the skills (`init`, `update`, `remove`, `status`) next to other agent packages without touching their files; `update` also replaces files of the same version whose content differs, and `status` tells a package that is not on npm from a registry it cannot reach.
