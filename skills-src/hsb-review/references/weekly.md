# The weekly review

This reference holds the steps of the weekly review. The rules that hold for the whole vault are in `HYPER-SECOND-BRAIN.md`, the rules of placing in `../hsb-place-an-item/SKILL.md`, and the Project List in `../hsb-projects/references/project-list.md`; this file names them and does not repeat them.

## What the weekly review is for

The weekly review resets the vault in minutes: the Inbox is empty, the Project List names what the user is committed to now, and the vault follows the user's current roles and interests. Keep it to the steps below; a deeper look belongs to the monthly review.

## The steps

1. **The Inbox.** Place every item in the Inbox, and in each extra Inbox folder that "Lasting choices" names, with the steps of `../hsb-place-an-item/SKILL.md`. When the Inbox holds about 50 items or more, first offer the user the choice between placing them and archiving the whole Inbox in one move (`inbox-archive.md`), and follow the answer. As you read the items, note each follow-up action they imply (a reply someone waits for, a deadline, a decision to make): the report lists them as tasks.
2. **The projects.** Review the Project List with the user as `../hsb-projects/references/project-list.md` → "Reviewing the list" says, with the open questions of `hsb-projects` that `list` gave you. In the same message, ask:
   - whether a role, responsibility, or interest of the user started or ended since the last review;
   - whether an area has slipped below the standard the user keeps up.
3. **Apply the answers.** Apply the answers about projects with `../hsb-projects/references/lifecycle.md`. Handle a role, responsibility, or interest that started or ended with `changes.md` → "Moving material after a change", and an area below its standard with the first two steps of `changes.md` → "Reflecting on areas and resources", for that area only.
4. **The additions** below, in one message after the three steps.

Done when every Inbox item is placed, archived with the Inbox, or waits for the user's answer as `hsb-place-an-item` says; the Project List has been reviewed with the user; the user has been asked about changes in roles, responsibilities, and interests and about areas below their standard; every answer is applied; and the additions have been offered.

## Additions

- **Bare links.** A note outside Archives that holds little more than a web link is a read-later item. Show the user up to five of them, and ask for each whether it stays for later or goes to Archives; move each as the user says. Skip this when the vault has none.
- **Other inboxes.** Ask once whether the user's other inboxes hold anything for the vault: action items and notes in email, follow-ups and preparations in the calendar for the past two weeks and the coming two, files on the desktop. Offer to take the text the user gives you into the Inbox, and place it in this review.
- **A first output.** When a project near the top of the list keeps gathering material but its folder holds no draft or other output, suggest the smallest piece the user could produce from it (`hsb-create`). Skip this when every top project has one.
- **Favorite problems.** When a "Favorite problems note:" line under "Lasting choices" gives a path, test every item placed in step 1 against each question in that note, and name in the report the strongest hits, three at most, each with the question it bears on. Skip this without such a note.
