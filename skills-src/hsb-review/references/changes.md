# Changes in the user's roles and interests

This reference holds the moving of material after a change in the user's roles, responsibilities, or interests, and the reflection on areas and resources. The categories are in `HYPER-SECOND-BRAIN.md` → "Categories", and the tests that tell them apart in `../hsb-place-an-item/references/placement.md`; this file names them and does not repeat them.

## Contents
- Why material moves
- Moving material after a change
- Reflecting on areas and resources

## Why material moves

The category of an item follows the user's relationship to it, and that relationship keeps changing. Material that never changes category goes stale, so keep it moving toward the user's current work: promote an item to a more actionable category when the relationship grows closer, and demote it when the relationship fades.

## Moving material after a change

Use this when the user says that a role, responsibility, goal, or interest of theirs started or ended (a promotion, a new duty, a new hobby, a duty handed over, an interest dropped), and when a review's question brings such a change up.

1. Name the change in one line. Search the vault for the material it touches: material that now serves the user's current work, and material that no longer does. Search the folder names and the note titles first, then the text of the notes, and open only the found notes that the change may touch.
2. For each item or folder found, test the user's relationship to it now (`../hsb-place-an-item/references/placement.md` → "Telling projects from areas", "Telling areas from resources"). Promote it when the matching category is more actionable than its current one, and demote it when it is less actionable.
3. When the change calls for an area or a project the user has not named, propose it and wait for the yes. Start a confirmed project with `../hsb-projects/references/lifecycle.md` → "Starting a project".
4. Show the user the moves in one list, each with its current place and its new place, and apply them after the yes. A folder that moves to another category takes the name form of that category (`HYPER-SECOND-BRAIN.md` → "Folders and names"); repair the links (`HYPER-SECOND-BRAIN.md` → "Links").

Done when every item the change touches sits in the category that matches the user's relationship to it now, or waits for the user's answer.

The moves to expect:
- Resources → Areas: the user takes on a responsibility or a habit, such as cooking at home to eat better. Move the few resources that help the user start, such as a handful of easy recipes, so that the user acts instead of researching further.
- Areas → Projects: a one-time effort grows out of a responsibility. Start the project from the ideas the area already holds.
- Projects → Areas: a project's result becomes routine, such as a training plan that becomes an exercise area.
- Areas → Resources: the user wants to share what an area holds, such as a list of event venues. Move the material that is free of personal and sensitive details and clear to others into a Resources folder for its topic; leave the rest in the area and tell the user.
- Areas and Resources → Archives: the user gives up a responsibility or loses interest in a topic. Move the folder to Archives under its own name.
- Archives → Projects: past work serves a new effort, such as the plans of an event the user ran before (`../hsb-projects/references/lifecycle.md` → "Starting a project").

## Reflecting on areas and resources

Use this when a review shows an area below its standard or an interest changing, in the areas step of the monthly review, and when the user asks to step back and think about the long term.

1. For each area under review, take its standard from the purpose in the area's `_about.md`, or ask the user for it, and ask whether the user is meeting it. When the user states a standard that the file lacks, write it into that purpose (`folder-about.md` → "What goes in it"), creating the area's `_about.md` when it has none, and tell the user, so that the next review starts from it.
2. For an area below its standard, ask what would help: a project, a habit, a routine, or a practice to start, stop, or change. Create projects with `../hsb-projects/references/lifecycle.md` → "Projects from efforts", and bring in the resources that would help ("Moving material after a change").
3. Ask about the resources: which interests the user wants to pursue more seriously, which questions they want to explore, and which hobbies have stalled and could start again. Promote what the user wants to pursue, from Archives as well ("Moving material after a change").

Done when each area under review has a standard and an answer on whether it holds, and each answer is applied.
