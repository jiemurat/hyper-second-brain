# What to keep

This reference holds the test of what is worth keeping, and how the user starts small. The rules that hold for the whole vault are in `HYPER-SECOND-BRAIN.md`, and the rules of placing in `../hsb-place-an-item/SKILL.md`; this file names them and does not repeat them.

## Contents
- Deciding what to keep
- Starting small

## Deciding what to keep

Use this when the user asks whether something is worth keeping or which of several items to keep, and when you choose the parts of a source (`source.md` → "A note from a source"). Every kept item costs the future reader time, so keep few.

1. **The user's reaction.** An item the user says moves, surprises, or excites them (they highlighted it, praise it, or ask to keep it) is worth keeping on that signal alone. Keep it and ask no reason.
2. **Four questions.** Without that signal, keep an item that gets a clear yes to one of them:
   - Inspiring: is it a quote, an image, an idea, or a story the user would return to for a lift or a fresh view?
   - Useful: could it later solve a problem, save time, explain a concept, or teach from experience, in one of the user's projects, areas, or resources? Name what it will let the user do, which problem it helps solve, or which obstacle it removes; being interesting is no reason.
   - Personal: is it the user's own thought, reflection, memory, or memento, or a work product of theirs such as a plan, an agenda, or a draft?
   - Surprising: does it contradict what the user's notes already hold?

   An item that may help answer one of the user's favorite problems (`favorite-problems.md`) is useful.
3. **Check the vault.** Search for the item's key terms with the script (SKILL.md, step 3). Leave out an item whose substance the vault already holds, and name that note. Favor an item that contradicts a note, and name that note: new thinking starts at a contradiction, and a vault that only confirms teaches nothing.
4. **Other platforms.** An item whose kind another platform suits (an appointment, a task, a document shared with others, a secret) is kept in the vault whatever the four questions say: remind the user of that platform as `../hsb-place-an-item/references/placement.md` → "Other platforms" says.
5. **Answer, then save.** Give each item a verdict, keep or leave, with the reason in one line that names the question it passed or failed. When the user asked you to keep the worthy items, save each kept item now as its own note, with its source line when it has a source (`source.md` → "A note from a source", step 3), and place it with `../hsb-place-an-item/SKILL.md`. When the user only asked whether, save what they then choose.

Done when every item has a verdict with its reason, and every kept item the user asked to save sits in its place.

## Starting small

Use this when the user asks what to start capturing, or how to start. A few kinds of content kept every week beat a full system the user does not use.

1. Ask which two or three kinds of content the user already has the most of and values (book highlights, meeting notes, voice memos, articles, photos).
2. Record the answer under "Lasting choices" in `project.md` as the line `- Kinds of content to capture: <kinds>`, as `HYPER-SECOND-BRAIN.md` → "What you may do and what you ask first" says for lasting choices.
3. For each kind, tell the user how its text reaches the vault: handed to you in the chat, or taken into the Inbox from its app (`source.md` → "Findings from other apps"). Add a kind later when the user asks.

Done when the line is under "Lasting choices" and the user knows how each kind reaches the vault.
