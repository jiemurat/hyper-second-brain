# Favorite problems

The user's favorite problems are a short list of open questions they keep coming back to. The questions stay fairly constant across jobs, projects, and years, so material tied to them stays useful for long. The list is a standing filter for what to keep and a lens for the weekly review. The rules that hold for the whole vault are in `HYPER-SECOND-BRAIN.md`; this file names them and does not repeat them.

## Contents

## The note

A line under "Lasting choices" in `project.md` gives the note's path, `- Favorite problems note: <path in the vault>`, or says that the user wants none, `- Favorite problems note: none`.

- When "Lasting choices" says neither and the user asks for the list, build it as "Building the list" says.
- Otherwise offer the list at most once, in the report of a request about what to keep. When the user already keeps such a list, record its path; when they want none, record that, and offer it no more.

## Building the list

Use this when the user has no list and wants one.

1. Ask for the open-ended questions the user has always been interested in, grand or practical, about work, health, relationships, learning, or society. Suggest that they ask people close to them what they were obsessed with as a child, since such interests often last.
2. Write each as a question that can have more than one answer, in the user's words. When a phrase of the user is no question, offer a wording and use it after their yes. A few questions are enough to start; twelve is a target, not a requirement.
3. Save the list as its own note, with the title "Favorite problems" in the user's language and one question per list item. It is personal, so it goes to an area, not to Resources: the area folder the user chooses, where an area the user has not named needs their yes first. Place the note with the steps of `../hsb-place-an-item/SKILL.md`.
4. Record the line `- Favorite problems note: <path in the vault>` under "Lasting choices" in `project.md`, and tell the user.

Done when the note sits in the chosen area with the user's questions in their words, and its line is under "Lasting choices".

## Changing the list

When the user's framing of a question changes, or they add or drop a question, write the change they state into the note, in their words. The questions persist while their wording moves. Done when the note holds the questions as the user now puts them.

## Using the list

- What to keep: an item that may help answer a question is useful (`keeping.md` → "Deciding what to keep").
- The weekly review tests the new items against each question (`hsb-review`).
