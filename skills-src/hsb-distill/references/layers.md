# The layers

This reference holds the layers of a distilled note, the marking convention, meeting notes, learning, and the summary. The rules that hold for the whole vault are in `HYPER-SECOND-BRAIN.md`; this file names them and does not repeat them.

## Contents

- The summary

## The marking convention

A line under "Lasting choices" in `project.md` gives the convention, `- Marking: bold (**...**) for layer 2, highlight (==...==) for layer 3`, or another the user chose.

- When you are about to mark a note and there is no such line, look at a few notes the user marked themselves (search for `**` and `==`). When they mark the same way, or not at all, use the convention above: write its line under "Lasting choices" in the form `HYPER-SECOND-BRAIN.md` → "What you may do and what you ask first" gives, and tell the user that they can change it. When they mark another way, ask the user once which to use, and record the answer.
- When the user's tool shows no highlight, underline (`<u>...</u>`) takes its place.

Done when the convention is recorded under "Lasting choices".

## Distilling a note

Distill just in time, when a note is about to be used: a note no one needs yet stays as captured.

1. **Layer 1** is the text as captured. Leave it as it is.
2. **Layer 2: bold the main points**: keywords that hint at what a passage is about, phrases that carry the source's message, and sentences the user would want to see first. Choose in this order: what the user already highlighted or commented on; what passes the questions in `../hsb-capture/references/keeping.md` → "Deciding what to keep"; what bears on a current project or a favorite problem. Keep it to about a fifth of the text.
3. **Layer 3: highlight the best of the bold**, when the note is long or valuable: the most interesting and surprising points, often one or two sentences, about a fifth of the bold at most. Put the highlight inside the bold (`**==...==**`).

Done when the gist of the note is clear within about thirty seconds from its marked passages alone. Test it by reading back only those passages: too many marks hide the point, too few leave it out.

## Meeting notes

Bold every decision and action item, and highlight the decisions, whatever their share of the note. List each action item in the report as a task for the user's to-do list, with the project or area it belongs to. Done when every decision and action item of the note is marked, and every action item is in the report.

## Learning

When the user wants to learn the material, the marking is part of how they learn it: gather the passages for them and leave the marking to the user. List the notes in the chat, with the title and folder of each, and under each the passages that carry its main points, each pointed to by the heading it sits under and its first few words in the note's language, so that the user reads the passage in the note itself; retell nothing, and change no note. Done when the user has the list and no note changed.

## The summary

A summary is layer 4, used rarely: a few bullet points, five at most, each one short sentence of about twenty words in plain words, with each unusual term explained, for a reader who remembers nothing of the source. In the chat, write it in the user's language; in the note, in the note's language. Write it from the bold and highlighted passages when the note has them, else from the text.

- When the user asks for a summary of a note, give it in the chat, and offer to add it to the top of the note.
- When the user asks you to add a summary, or says yes to the offer, put it at the top of the note, below the title, under a heading meaning "Summary" in the note's language. Nothing else in the note changes.
- Offer a summary for a note the user keeps coming back to, as one of the improvements in your report.

Done when the summary reads clearly on its own, and the note is unchanged unless the user asked for the summary in it.
