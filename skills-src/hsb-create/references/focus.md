# Focus: focused work, the two modes, and the "Where I left off" note

This reference holds the preparation of focused work, the two modes of creative work, the "Where I left off" note of a project, help for an overwhelmed user, and the final entry of a project that stops. The rules that hold for the whole vault are in `HYPER-SECOND-BRAIN.md`; this file names them and does not repeat them.

## Contents
- Preparing focused work
- Exploring or finishing
- The Where I left off note
- One project at a time
- When a project stops

## Preparing focused work

Use this when the user asks what to work on, or says they are about to focus on a project, online or offline. Time spent gathering material once the work has started is the cost to remove.

1. Name the projects: the ones the user names, or the handful at the top of the Project List. Put the most time-sensitive first: overdue projects, then the nearest timeframes.
2. For each project, read the latest entry of its "Where I left off" note first (when it has none, start from its notes), then the notes in its folder. State the next steps that move it forward, taken from the user's words and the project's notes; ask the user when you cannot tell.
3. Check that the project's folder holds the material those steps need. Find the missing material in the rest of the vault (`../hsb-find/SKILL.md`), list each find with its title and folder, and bring it in on the user's yes (core rule 4). When a step needs content from the web, say so; a part of it is saved only on the user's yes, as a short note with its source line (`hsb-capture`).
4. When the user will work without a connection, remind them to make the Projects folder available offline in the app that syncs the vault, and the folder of each note the project links to; say which material lives only on another platform.

Done when, for each project, the user can take the next step with the connection off, or knows exactly what is missing.

## Exploring or finishing

Creative work has two modes. Exploring widens the space: gathering and trying many options. Finishing narrows it: cutting, choosing, and ordering until the piece is done. Use this when the user sits down to move a piece forward, asks for more material or ideas, or wants to finish.

1. Learn the mode the user wants; ask when it is unclear. A near deadline, a folder that already holds plenty, or an existing draft point to finishing.
2. Exploring: search widely (`../hsb-find/SKILL.md`, the four ways to find), offer sources and connections across areas and ages, and show each find by its title and folder. Material goes into the project's folder only on the user's yes (core rule 4).
3. Finishing: work only from what the project's folder holds and bring in no new source. Propose in the chat what to cut and an order for the rest; the user's draft changes only with a yes. Write the parts the user cuts into the project's note of ideas kept for later, the one `hsb-projects` writes when it shrinks a project, or a new one in the project's folder: nothing cut is lost. To begin, propose a short fixed time, fifteen or twenty minutes, and the smallest version that could earn feedback.
4. When the user is meant to be finishing and keeps asking for more, say that the folder already holds enough and offer the smallest finishing step: more research feels like progress and puts the finish off.
5. When a finishing round ends and the work goes on, carry what it taught (a gap, a question, a weak part) into the next exploring round: the two modes take turns until the user calls the work done.

Done when your help matches the mode the user named, and every cut part sits in the note of ideas kept for later.

## The Where I left off note

One note per project keeps the momentum of a work session for the next one. Its title means "Where I left off" in the language of the project's notes; find an existing one by that meaning, in any language.

1. Offer an entry once when the user ends a work session on a project (they say they are stopping, or the work you did together is done). Write it when the user says yes or asks for it.
2. Write a dated entry (`YYYY-MM-DD` as its heading) at the top of the note, above the older entries, with four parts, in whatever shape suits the user:
   - the next steps as they now seem;
   - the current status: the biggest challenge, the most important open question, the roadblocks to expect;
   - the details likely to be forgotten once the user steps away;
   - the intention for the next session.

   Take each part from what the user said in the session and from the notes that changed, and carry over from the previous entry each detail that still holds; ask for a part you cannot fill, and invent none.
3. When the user works on a draft, a beta, or a proposal, offer to send it to one person for feedback while they are away: the user sends it.
4. When the user returns to the project, read the latest entry first and start from it (`Preparing focused work`, step 2).

Done when the note holds a dated entry with the four parts at its top, and the next session can start from it without any other context.

## One project at a time

Use this when the user feels overwhelmed and `hsb-projects` has reviewed the list with them, or when they ask for help with work while stretched thin. Scale back instead of adding: help only with the project at the top of the list, offer only the notes that project needs, and take it through to its next finished piece before you turn to the next project. Leave the rest of the vault where it is. Done when the user has the next step of that one project and the notes it needs.

## When a project stops

Use this when `hsb-projects` finishes a project that is paused, cancelled, or handed over, before its folder moves to Archives. Offer a final entry in its "Where I left off" note, and write it on the user's yes as a dated entry at the top, with these parts in place of the usual four: the last actions, why it stopped, who worked on it and in what role, and the lessons the user names (none when the user skips them). Done when the final entry is at the top of the note, or the user declined it.
