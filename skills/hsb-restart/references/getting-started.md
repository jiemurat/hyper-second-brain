# Getting started

This reference holds the stages of getting started with a second brain, for a new user or one who starts the knowledge work afresh. A few small habits that last beat a full system the user does not use: take one stage at a time, and move on only when the user is ready. Whatever the stage, four things stay open to the user: keep what resonates, organize for action, find the gist, and show the work.

## Contents

## The stages

| Stage | What the user does | The skill that does it |
|---|---|---|
| 1 | Decide what to capture: the two or three kinds of content they have the most of and value | `hsb-capture` (starting small) |
| 2 | Set up PARA, with a folder and a list entry for each current project | `hsb-init` when the vault is not set up, then `hsb-projects` (building the list) |
| 3 | Build the list of favorite problems | `hsb-capture` (favorite problems) |
| 4 | Bring the highlights, voice memos, and clippings they already make into the Inbox | `hsb-capture` (findings from other apps) |
| 5 | Practice distilling on the notes of one current project | `hsb-distill` |
| 6 | Make one reusable piece for a project, and show it to one person | `hsb-create` (pieces worth reusing, showing early) |
| 7 | Move one deliverable forward with only the notes the vault holds | `hsb-create` (finishing) |
| 8 | Keep the weekly review, and a month later the monthly review | `hsb-review` |

## The steps

1. Take the last stage the user finished from the line `- Getting started: stage <n> of 8, <YYYY-MM-DD>` under "Lasting choices"; the next one is stage n + 1, and without the line it is stage 1.
2. Tell the user the stage and what it asks of them, and ask whether they want to take it now.
3. On the yes, do the stage with the steps of the skill the table names (the skills sit in the folders next to this skill's folder: open `../<skill>/SKILL.md`).
4. Write or update the line under "Lasting choices" as `HYPER-SECOND-BRAIN.md` → "What you may do and what you ask first" says, with the stage the user finished and today's date, and tell the user the next stage. Offer the next stage only when the user says they are ready.

Done when the user has taken the stage they chose, the line under "Lasting choices" names it, and the user knows the next one.
