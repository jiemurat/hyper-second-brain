# Capturing from a source

This reference holds the note from a source and the findings from other apps. The rules that hold for the whole vault are in `HYPER-SECOND-BRAIN.md`, and the rules of placing in `../hsb-place-an-item/SKILL.md`; this file names them and does not repeat them.

## Contents
- A note from a source
- Sources you cannot open
- Findings from other apps

## A note from a source

Use this when the user asks you to keep the key points of an article, a book, a transcript, a video, a podcast, or a website, and when you choose what to keep from one. A source the user hands over to keep whole is saved as handed, with `../hsb-place-an-item/SKILL.md`.

1. **Read it.** Open the source and read it through. When you cannot, follow "Sources you cannot open".
2. **Choose.** The value of a source is uneven. Take the passages, quotes, and images that pass `keeping.md` → "Deciding what to keep", and every part the user highlighted or named; leave out whole sections.
3. **Write one note.**
   - The chosen parts, quoted word for word or summarized closely, under the source's own headings and in its bullet lists where they carry structure. Together they stay within about a tenth of the source's text.
   - A source line: `Source: <title>, <author or publisher>, <date published>, <address>`, leaving out a part the source does not give. A link never stands alone in the note.
   - When the user said why it matters or what caught their attention, a line with that in the user's words.

   Write the parts so that the note reads without opening the source, and title it as `HYPER-SECOND-BRAIN.md` → "Notes" says.
4. **Place it.** Follow `../hsb-place-an-item/SKILL.md` with the note as the item, so that it sits with the project, area, or resource it serves.

Done when the note holds only the chosen parts within about a tenth of the source, carries the source line and the user's reason when they gave one, reads without the source, and sits in its place.

## Sources you cannot open

A video or a podcast without a transcript, a paywalled page, a file you cannot read: ask the user for the transcript, the text, or their highlights, and build the note from what they give you. Write nothing from memory or from what the title suggests. Done when the note is built from text you read, or the user has been asked for it.

## Findings from other apps

Use this when the user mentions highlights from a reading app, voice-memo transcripts, forwarded emails, or notes in another app that should reach the vault. Findings scattered across many places are not found when they are needed.

1. Offer to take their text into the Inbox: the text the user pastes, or the exported file the user names.
2. Write one note per source (one book, one voice memo, one email) in the Inbox folder, titled by its source, with the text as the user gave it and a source line in the form above, filled with what the text tells. The user's highlights are already chosen: keep them whole, and sort nothing now.
3. Tell the user that the weekly review places them (`hsb-review`); place them now only when the user asks, with `../hsb-place-an-item/SKILL.md`.

Done when each source has one note in the Inbox with its source line, and the user knows when the notes will be placed.
